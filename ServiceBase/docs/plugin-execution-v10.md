# 插件执行与归档清单（执行器 v10）

此规则替代 v5–v9 文档中插件导入后逐文件内容、数量、meta/GUID 核对以及失败占锁的规则。单独的插件替换更新 `plugin_update` 仍使用原来的备份与替换流程。

## 导入完成判定

- 下载制品和暂存归档仍验证大小、SHA-256、来源清单及安全路径，避免损坏归档或路径越界。
- 写入前保存归档路径、原有文件状态和不可覆盖的执行意图；调用前保存 `invoked`。Unity 空闲后按导入回调或域重载后的执行日志完成本项，不再遍历工程验证导入内容、数量、meta 或 GUID。
- 插件自己改写 DLL、删除过期文件或生成资源，不影响导入完成；这些额外产物不会加入归属清单。缺失的归档父目录仍纳入清单，供删除时清理空目录。
- `archive-execution-v1` 回执只校验路径范围与原归档一致；服务端不接受额外生成文件进入删除清单。本地记录包含 `import_result`，完成导入与失败后保留记录可以区分。
- 重复导入同一构建保留第一次的原有文件信息；不重新要求工程内容匹配归档。首次导入仍拒绝覆盖内容不同且未归属于该构建的现存文件，拒绝路径类型和 GUID 冲突。
- 老任务已经写入但没有完成回调时，保存归档清单、标为未知并跳过，不重复导入、不伪造成功。

## 失败与队列

- 安装计划中的插件导入失败、取消、编译报错或未确认完成：保存原因及可用清单，步骤标为跳过，移除最终核对中对应的插件目标；服务收到终态且 Unity 归档确认后才派发下一项。
- 下载十分钟未完成则按未写入失败；归档回执回传两分钟仍未成功则保留本地清单并跳过。服务断连时只能等待恢复连接后提交结果，不能绕过服务独立派发下一项。
- UPM 包明确失败或空闲核对十分钟仍未满足目标：计划失败，尚未执行步骤跳过，释放服务队列。UPM 的 manifest、lock、注册信息及最终包图校验保留。
- 插件编译报错不会阻止后续 UPM 包安装或最终包图核对，但 Unity 仍在编译、资源刷新或播放切换时不会并发开始下一项。已加载的执行器可以继续运行；若关闭 Unity 后工程仍有编译错误，必须先恢复脚本编译，执行器源码才能重新加载。
- 跳过不回滚已经导入的部分文件；插件记录保留，用户可以查看原因或发起删除。磁盘日志损坏、执行器未加载、编辑器持续忙碌仍需处理实际阻塞，服务不假定操作完成。

## 状态与删除

插件状态页展示“已保存导入记录”，不把它解释为所有资源完整。刷新读取 Unity 自己的记录，不再扫描文件哈希或处理插件生成产物。

删除以该记录中的归档清单为范围：

1. 其他插件记录、已手动迁移的旧插件记录或其他 Assets 本地包占用的路径保留；损坏的归属记录导致预检失败，不能忽略未知引用。
2. 未共享的归档文件移至 `.servicebase/plugins/trash/<attempt>/`，即使文件已修改或导入前就存在。对应 meta 存在时一并移出，不要求其内容或 GUID 匹配。
3. 文件消失视为无需删除；路径类型改变则保留。先处理文件，再从深到浅清理空父目录。额外产物、用户文件或共享子项使目录保留，绝不递归删除整个根目录。
4. 原归属记录、逐项结果和移出的文件仍保留备份；删除遇到部分写入异常继续使用原有人工核对流程，不反复执行删除。

## 升级

服务端更新代码及静态资源，无新增数据库迁移。完整同步 `unity/UpmExecutor/` 并保留已有 `.meta`，等待执行器版本 10 上报。v10 会接管本地仍有完整日志、停在核对阶段的旧插件导入；自动恢复仅核对执行日志并提交结果。

旧回执重放时，新版序列化多出的 `operation_finished: false` 与缺省值视为相同，不改写旧审计事件。将其改成 true、修改消息或其他字段仍按同序号内容冲突拒绝，避免升级本身触发“同步回执被拒绝”。

网页请求超时显示中文说明并保留上次状态，轮询继续重试。页面超时不会取消已经提交的后台任务；真正的服务或网络中断仍需恢复连接。
