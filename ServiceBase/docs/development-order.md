### 5. 单条 unitypackage 导入与工程记录（已完成当前支持范围）

- 制品鉴权下载、临时缓存、大小/SHA-256 校验。
- 导入前保存文件路径、GUID、哈希与已有文件基线，识别覆盖和共享文件冲突。
- 独立导入器：一次导入、回调记录、域重载后核对成功/失败/取消/部分导入，不能仅凭目录存在判成功。
- 建立 ServiceBase 自有文件归属与插件安装记录；标签页显示所选工程状态并支持单插件导入。

验收：从网页选插件到 Unity 导入、核验、回执、工程状态展示闭环。归属记录是以后删除的基础。

### 6. 单条 ZIP 导入（已支持网页预选根目录）

- 导入前由用户在网页浏览当前工程 Assets 目录并选择根目录，随任务持久化；Unity 无交互地自动执行，保留 ZIP 原有结构。
- 限制解压大小、路径穿越及符号链接，保留 .meta，复用冲突检查和归属日志。
- 支持部分应用后的恢复核对，不把所有 ZIP 一律解压到 Assets/Plugins。

验收：ZIP 支持网页选目录、确认前取消、重载恢复和逐文件核验；不再需要预设布局。需要 Assets 外目录的用途仍不支持。

### 7. 服务端安装计划解析与预览（已完成当前支持范围）

- 读取所选发布版本的完整元数据，将 tag 固定到 commit；按精确包版本索引插件，缺映射不借用其他版本。
- 合并标准 UPM 依赖、dependenciesGit、工程已有约束，检查 Unity 要求、版本冲突与循环；拓扑排序并去重。
- 安装前用弹窗列表展示依赖树将新增/变更的包；每个包可展开查看附带插件，逐个复选是否导入，ZIP 根目录同时在网页预选。
- 对选中插件间的同文件冲突（包括不同版本）提示警告，允许继续确认安装；精确重复制品可去重，不能将不同版本静默合并。
- 按依赖先于根包的顺序生成包步骤，并在每个包步骤之前插入其已选插件导入步骤；明确处理编译前置约束。
- 输出不可变计划与预览；先接通目录选包到预览，实际批量执行在下一步接入。

验收：输出明确的包链接、固定版本/commit、插件构建及先依赖后根的可执行顺序。

## 下一步准备：10. MTP 共存边界与真实工程验收

状态：已整理范围，尚未开始实现。目标是让现有业务工程具备明确、经过验证的服务操作条件。

### 已确认的阻断点

- `unity/UpmExecutor/MtpBoundary.cs` 当前按 MTP 身份阻止新修改；停用 Bridge 读取没有解除这个限制。
- Pack Test 当前 MTP 的 `Editor/Entry/MTPApplicationStarter.cs` 在脚本重载后自动调用安装恢复与清单同步。这些回调由 Unity 触发，ServiceBase 不调用 MTP API 也不能阻止它们执行。
- 当前 MTP 的安装进度路径是 `Library/MTPCache/mtp-install-progress.json`，服务边界目前只检查 `Library/` 下的旧路径；后续边界设计须同时覆盖版本差异。现有程序集身份拦截仍有效，尚未因此开放修改。

### 依次推进

1. **确定共存方案与支持范围**：检查当前使用的 MTP 版本、自动业务入口、运行中和未收尾操作，明确保留 MTP 时的避让机制。若需要 MTP 侧配合，列出具体改动；ServiceBase 执行器继续不引用其类型、程序集和业务 API。
2. **落实工程互斥和恢复边界**：覆盖双方启动、域重载、退出、断线及未完成任务；未知版本继续给出明确诊断。完成协议和验证前保留现有拦截。
3. **在独立测试工程验证真实仓库样本**：覆盖根包及依赖、附带 unitypackage、网页选目录的 ZIP，再验证更新、卸载和共享资源保护。样本固定版本与 commit；不直接在业务工程试装。
4. **补齐故障验收并给出可用范围**：验证切后台、域重载、编译错误、断网、服务及 Unity 重启；确认任务不重复执行，MTP 不启动额外的安装、插件导入或清单改写业务。

完成标准：能够明确说明哪些 MTP/Unity 组合可执行，以及每个组合的验证证据；网页显示具体阻断原因。通过验收的组合才按设计开放服务操作。

后续再安排仓库上传/发布、插件元数据编辑、包到插件映射管理与新版打包器对接。手动同步 MTP 数据保持单独待办。
