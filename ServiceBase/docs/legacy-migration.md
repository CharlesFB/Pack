# 独立 Assets 包识别与可选旧记录迁移（v9）

## 使用

1. 服务端应用迁移 `0013_legacy_migration`，更新静态文件；Unity 整体更新 `unity/`（包括 `UpmExecutor` 和 asmdef，保留已有 `.meta`）。
2. 选择工程后，工程包页的 **Assets 本地包** 显示扫描到的名称、版本、目录及同名冲突。此扫描读取 Assets 中的 `package.json`，不读取 MTP 记录，也不调用 MTP 类型。
3. 若需要迁移历史信息，点击 **工程包** 标签页卡片下方的 **迁移 MTP 本机记录** 按钮，在弹窗内点击 **读取旧记录并预览**。
4. 预览中的复选框默认全部不选。选中需要的条目后点击 **迁移所选记录**，在任务区查看完成结果。原始记录与 Assets 文件不作修改。
5. 下方 **已迁移记录** 显示当前文件与迁移时基线的一致、修改或异常数量。包历史记录只作来源参考，当前安装状态始终以独立扫描为准。

打开页面、连接 Unity、启动服务和点击普通刷新均不会触发旧记录扫描或迁移。点击迁移入口后的读取、确认分别是独立步骤。预览 30 分钟后或更换编辑器会话后失效；等待超过 90 秒显示连接提示，可主动重新读取。

## 支持的来源与权限

- `Packages/upm-install.json`：根包历史记录。
- `Packages/upm-local.json`、`Packages/ump-lock.json`：已知 `Dependencies` 结构的本地包记录。
- `Library/upm-dependencies.json`、`Library/MTPCache/upm-dependencies.json`：依赖历史记录。
- `Packages/plugin-assets.json`：`Content` 中按包名/插件文件名索引的资源路径。

只使用内置 JSON 解析器读取已知结构；未知结构返回明确错误，不调用 MTP 的反序列化或恢复入口。仅保留白名单展示字段和文件核对信息，旧 URL、Token、编译宏等不迁移、不上传。源文件 SHA-256 用于确认时检测变更，不上传原文。

旧插件路径列表不能证明“导入前不存在”或仓库的精确版本。因此本阶段迁移保存的是**历史来源和用户确认的现状基线**，不伪造 `build_id`，不生成普通导入所有权回执，不自动授权更新或删除。已迁移路径会被 Unity 的新插件删除/更新操作作为共享引用保护。若要取得可删除的归属，需另行提供原始导入基线并开发审查流程。

迁移记录在独立面板展示；仓库插件卡片的“已导入”仍只采用有精确构建证据的 ServiceBase 导入记录。原记录有文件缺失时允许保存历史基线，并明确显示异常。

## 独立包识别与保护

UPM 注册包和 Assets 包分别上报；同名 Assets 目录全部保留在界面中，显示冲突，不冒充 UPM 注册包。仅凭 `package.json` 不能证明包内文件完整。

Assets 元数据纳入计划基线，同名 UPM 安装受阻；Assets 包声明的依赖参与版本约束和卸载保护。Unity 在 Add/Remove 前再核对。本地包只提供识别、依赖保护与来源信息，不通过 UPM 入口移动或删除 Assets 目录。无法解析、越界或符号链接路径使扫描报错，需处理后再创建修改计划。

## 保存与恢复

- 服务端保存请求、摘要、不可变选择和任务；确认占用与安装相同的工程锁。
- `.servicebase/migrations/previews/<id>.json`：用户请求的完整本机预览，含源摘要及逐文件基线。
- `.servicebase/migrations/records/<id>.json`：确认后写入的一份不可变选中记录。
- `.servicebase/upm/active.json`、`intents/`、`history/`：复用任务日志。

单次预览最多 500 条记录、20,000 项资源；累计迁移最多 500 条记录。超过限制会在写入前拒绝，避免生成无法完整展示和核对的记录。

确认执行前再次检查旧文件摘要、实际资源和是否已经迁移。用临时文件原子落盘；同一请求重传或重启时核对并复用同一份归档，不重复创建记录，不覆盖不同内容。记录迁移仅增加 ServiceBase 自有文件，因此可在检测到 MTP 时执行；资源安装、卸载、导入、更新仍遵守 MTP 共存拦截。日志损坏时不领取迁移任务。

`.servicebase/` 属于本机工程运行与恢复数据，应加入业务工程 Git 忽略并单独备份，不能随 Library 清理。v9 工程不能退回旧执行器继续修改，否则会绕过 Assets/迁移引用保护。

## Bridge 调整

`BridgePullClient` 只处理注册、心跳和消息，不再定时调用 `MtpSnapshotReader`，旧快照任务返回明确的停用说明。旧适配类暂留作历史测试材料，正常运行没有调用入口。设置变化由执行器自行检测并重新连接；存在未确认任务时设置页禁止更换服务器。
