# 插件导入、当前状态与删除（执行器 v6）

**当前状态及删除规则以 [v10 插件执行与归档清单](plugin-execution-v10.md) 为准。** 下文保留 v6 历史设计和验收；v10 按归档清单删除未共享文件，不再因内容变化或导入前存在而保留。

第 9 步已补充包卸载和插件替换更新，需要 v8 与迁移 0012，详见 [包卸载与插件更新](package-maintenance.md)。

## 入口及升级

插件信息面板提供导入、核对工程插件状态，以及每条导入记录的删除按钮。ZIP 仍在网页选择 Assets 内的现有根目录；记录按实际导入目录独立展示和删除。再次导入其他目录仍执行 GUID 冲突检查，不保证同一制品能在同一工程内重复放置。

- 服务端迁移 `0010_plugininventory_pluginremovalreceipt`，更新静态资源并重启。
- Unity 完整更新 `unity/UpmExecutor/`，执行器版本 6；保留原有 `.meta`。版本 2–5 保持原先支持的操作，不能接收删除任务。
- 不引用 MTP 的类、事件、业务接口或本地记录。原有 MTP 阻止边界继续生效；已识别的 MTP 工程可以只读核对，新导入/删除仍被阻止。严格共存和旧 MTP 记录迁移不在本次范围。

## 实现分工

- `PluginInventory.cs`：读取 Unity 工程自身的插件归属记录，逐文件核对类型、内容 SHA-256、meta SHA-256、GUID 及 Unity 注册路径，生成本地状态快照。
- `PluginRemover.cs`：独立删除计划、备份移出、日志恢复、逐项核对与不可变回执。
- `UpmExecutor.cs`：v6 同步协议接入状态快照、网页重新核对请求和删除任务，继续共用工程串行锁、意图文件、域重载恢复。
- `dashboard/plugin_inventory.py`：保存工程/会话限定的状态快照，校验扫描新鲜度、解析精确删除目标。
- `plugin_installations.py`：保留导入下载和归属回执；增加删除回执验证与按工程展示的状态/删除摘要。
- `plugins.js`：面板状态、核对按钮、按导入目录删除、网页确认框及轮询；任务列表标明导入或删除。

## Unity 是状态来源

本地文件：

- `.servicebase/plugins/records/*.json`：每次成功导入后的文件归属，保留首次导入前已有文件信息。
- `.servicebase/plugins/status.json`：最近一次成功核对的当前状态。
- `.servicebase/plugins/removed/<attempt>.json`：删除前原始归属记录的不可变存档。
- `.servicebase/plugins/trash/<attempt>/Assets/...`：移出文件及 meta 的备份；目录本身只在空目录时删除。
- `.servicebase/upm/active.json`、`history/`、`intents/`：沿用任务日志，增加删除计划、逐项结果、回执和摘要。

核对发生在执行器启动后、工程资源变化后、导入/删除结束后、网页请求时，以及空闲时每 60 秒。文件之间分帧处理；编译、资源刷新、播放或已有修改任务期间暂缓扫描。单个大文件的哈希仍在 Editor 主线程完成，特别大的插件可能增加单帧耗时。

状态包括：完整、修改、全部缺失、部分缺失。完整要求文件、meta、GUID 均匹配；目录存在不代表插件完整。没有 ServiceBase 记录的手动导入和 MTP 插件显示为未纳入管理，不按目录名猜测版本。旧服务历史导入记录只作为历史提示。

快照通过原生鉴权的 sync 上报，绑定工程、设备凭据及当前编辑器会话。服务端保存在 `PluginInventory`；新会话、超过 120 秒未完成核对、离线、扫描报错时不能据此发起删除。数据库中的历史导入回执不能覆盖当前扫描结果。页面每 10 秒刷新状态，也可手动请求 Unity 核对。

## 删除规则

网页提交精确的记录标识和原始记录摘要。服务端要求当前状态已核对、存在对应的历史导入证据、v6 就绪且工程无其他活动任务。请求 UUID 幂等；删除目标一经建立不可变化。

Unity 在任何写入前重新检查所有本地归属记录、目标摘要、当前文件状态和共享引用。损坏记录导致预检失败；不因某个记录读不出就忽略它的共享引用。

逐项处理：

1. 本次插件创建、文件及 meta 未变化、没有其他活动插件记录引用：移至工程本地 trash 备份目录。
2. 导入前已经存在：保留。
3. 内容/meta/GUID 已改变：保留。
4. 其他插件仍引用：保留。
5. 已不存在：记录缺失，不重新生成。
6. 文件夹：先处理文件，再从深到浅仅删除空文件夹。用户额外文件、隐藏文件以及额外 meta 都会阻止整目录删除。

不会按根目录递归删除。删除完成会移除该导入记录；保留资源可能继续留在工程中，页面明确展示数量和路径摘要。因此“任务完成”表示按以上规则完成清理，不表示所有插件文件都已消失。共享文件的原始所有权暂不转移给剩余插件；最后一个插件删除后，原先作为已有文件使用的资源仍会保守保留。

移出的文件不自动清空；恢复需要停止其他工程修改，核对 `history` 与 `removed` 存档，手工恢复需要的文件/meta 及目录。当前没有一键撤销或备份清理功能。

## 中断与失败

- 未写入的明确预检失败释放任务锁；修复后刷新状态并重新提交删除。
- 写入前先落盘完整计划、原记录和不可覆盖的意图文件。文件移出后保存逐项结果，再刷新 Unity。
- 域重载或重启只核对已有计划，不重复执行删除。计划/原记录缺失、未完成移出、重新出现的资源、编译错误均进入“需要核对”，保留工程锁。
- 原记录先存入 removed，再移除活动记录；中途重启可验证同一存档后继续提交回执。
- 原生回执绑定派发的 Attempt，逐路径对应原导入证据，禁止声称删除原本已存在的文件。服务端保存不可变 `PluginRemovalReceipt` 后才接受成功状态。
- 网络超时重传同一回执；重复回执及重复成功确认不重复创建任务或执行修改。
- 部分移出不会自动回滚。人工核对并补齐计划所需结果后可点击“重新核对”；该按钮不重新删除资源。
